# AI Coding 说明

## 开发方式

这个公开项目用 AI Coding 协助完成代码重建与文档整理，但产品判断、公开范围、素材选择和验收边界由人确定。AI 在明确约束下读取规格、生成候选实现、检查字段与行为，再由人审阅运行结果和对外表述。

公开仓库不是让 AI 自由改写原工程，而是先把要展示的机制收窄，再为这些机制编写一套不含私有材料的离线实现。这样可以直接阅读和运行关键路径，同时避免把竞赛工程、官方原始资料、内部日志或完整 Prompt 链带入公开版本。

## 人与 AI 的分工

原项目为团队协作。本人负责产品、视觉、验收，并组织前端实现；技术同学主要负责数据、模型和后端，双方共同联调。公开重建沿用这些已经形成的产品机制，但不能据此把原项目全部工作归为个人成果，也不能声称产品由 AI 独立完成。

在本公开仓库中，AI Coding 主要用于：

- 按 V4.0 冻结规格梳理可公开的行为约束；
- 生成和修订标准库 Python、SQLite 与原生前端代码；
- 对照源码检查接口、状态、时点和文档是否一致；
- 发现容易混淆的表述，例如把“本地记录”写成“已经发送”。

人的工作包括确定范围、选择实现取舍、审查合成样例、核对界面与交互、决定哪些材料不能公开，并对最终版本负责。

## 约束如何进入代码

这次重建先固定几条可检查的规则，再写运行文件：

- 只使用 Python 标准库、SQLite 和浏览器原生能力；
- 服务只监听本机回环地址；
- 六条样例重新编写，不复制竞赛数据；
- 每次分析只读取当前消息时点可见的内容；
- 证据分为已核对记录、消费者自述和系统推断；
- 草稿必须经过人工查看，采纳、改写和拒绝分别记录；
- 高风险终稿需要额外核对；
- 写请求具有幂等保护，旧上下文不能继续采纳；
- 所有输出都保持“未发送、无真实业务执行”的状态。

这些约束分别落在 `samples.py`、`core.py`、`app.py` 和 `web/` 中，而不是只写在说明文档里。

## 可复核方式

AI Coding 的价值在这里不靠代码行数或效率百分比证明。读者可以直接检查：

1. `samples.py` 是否只含六条合成会话，以及五类服务是否都出现；
2. `core.py` 是否按消息序号过滤证据，并生成六步 Trace；
3. 草稿改动是否被区分为原样采纳与改写；
4. 重复请求和旧上下文是否有明确错误；
5. `app.py` 是否只绑定本地地址，前端是否始终标明未发送和无真实执行。

仓库中的运行结果只说明这份公开参考实现的行为。原项目历史报告中的用例数量或通过记录属于当时的 V4.0 工程证据，不能挪作本仓库的新测试成绩。

## 不公开的开发材料

本仓库不提供完整内部 Prompt 链、私有路径、原始日志、账号信息、官方数据原件或团队内部协作记录。`source_before_v41.zip` 是混合快照，不能作为精确原版 V4.0 的公开证明；本项目也不以该快照为可发布源码来源。更完整的来源说明见 [provenance.md](provenance.md)。
