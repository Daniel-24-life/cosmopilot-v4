# 架构说明

## 项目定位

本仓库是一个本地离线参考实现，用来展示知微 CosmoPilot V4.0 中几项可以公开说明的机制。它不是原竞赛工程的直接发布，也不是生产客服系统。当前实现只使用 Python 标准库、浏览器原生能力和 SQLite；不调用模型，不连接外部平台，也不会发送消息或执行退款、补发、建单等业务操作。

## 运行结构

```text
浏览器工作台
  ├─ GET /api/state       读取合成会话与本地反馈摘要
  ├─ POST /api/analyze   按会话和消息时点生成分析
  └─ POST /api/feedback  记录人工采纳、改写或拒绝
            │
            ▼
        app.py
  回环地址 HTTP 服务、请求约束、静态文件
            │
            ▼
        core.py
  六步分析、证据筛选、草稿校验、反馈与幂等
       │              │
       ▼              ▼
  samples.py        SQLite
  6 条合成样例      分析、上下文、反馈、幂等结果
```

`app.py` 只监听 `127.0.0.1`，并检查 Host、Origin、JSON 类型和请求体大小。它把业务请求交给 `core.py`，同时提供 `web/` 中的静态页面。SQLite 文件默认写入 `.runtime/demo.sqlite`，也可通过 `--db` 指定其他本地路径。

## 六步分析

`Store.analyze()` 对每次分析依次记录六个步骤：

1. 读取白名单输入：只取所选合成会话在当前消息序号前可见的内容。
2. 筛选时点证据：只保留 `available_seq` 不晚于所选时点的证据。
3. 选择服务路径：在五类固定服务中读取样例所属路径。
4. 列出核验缺口：把缺少的信息单独列出，不用推断补齐。
5. 准备候选草稿：完整时点使用样例草稿，较早时点使用保守提示。
6. 校验公开示例规则：检查有限的越权、医疗和结果承诺表述。

Trace 记录步骤名称、实际测得的本地耗时和 `local_rules` 来源，不记录思维链或完整 Prompt。这里的校验器只是公开演示用的窄规则，不代表全面合规审查。

## 证据与时点

公开样例使用三类证据：

- `verified`：对照了当前合成记录的事实；不表示现实世界或品牌系统已经核实。
- `buyer_report`：消费者在合成对话中的自述。
- `inference`：根据当前信息给出的系统建议。

消息时点由 `upto_seq` 控制。分析只读取不晚于该序号的消息和证据，因此可以比较同一会话在不同信息阶段的结果。`DEMO-006` 专门展示后续新增的签收信息不会出现在更早的回放中。

分析 ID 由当前可见消息、证据、草稿、会话、时点和公开版本共同计算。瞬时耗时不参与哈希，因此同一上下文可以得到稳定标识。

## 人工决策与状态保护

候选草稿始终是未发送文本。用户可以：

- 原样采纳并记录；
- 修改后采纳，记录为 `adopt_edited`；
- 拒绝建议，记录为 `rejected`。

高风险样例要求人工先核对证据和措辞。终稿提交时会再次经过公开示例规则检查。反馈只写入本地 SQLite，不改变源工单，也没有对外发送能力。

每次反馈必须带 `Idempotency-Key`。同一键和同一请求重试时返回原结果；同一键用于不同内容时返回 `IDEMPOTENCY_CONFLICT`。如果会话已经产生了更新的分析，旧分析的采纳请求会返回 `STALE_CONTEXT`，输入草稿不会因此被覆盖。

## 有意保留的限制

这是机制展示，不是原系统的完整移植。当前版本没有在线模型、真实业务数据、账户与权限体系、外部消息通道、生产审计、完整政策库或平台写操作。六条样例全部为本仓库独立编写的合成内容。完整公开范围见 [public-scope.md](public-scope.md)，来源关系见 [provenance.md](provenance.md)。
